## 2. Цель первой поставки (MVP = «Минимальный прототип» из документа)

1. Реальная комната видна через passthrough.
2. Виртуальная стойка ПВЗ, поставленная игроком на пол.
3. Один виртуальный клиент.
4. Три реальные коробки с тремя разными QR-кодами (`BOX-001..003`).
5. Сканирование коробок.
6. Один случайный заказ.
7. Проверка, что отсканирована правильная коробка.
8. Передача заказа клиенту у стойки.
9. Сообщение об успешной выдаче.

**Критерий готовности MVP:** на Quest человек, не участвовавший в разработке, проходит цикл «клиент → поиск → скан → выдача → клиент ушёл» 3 раза подряд без подсказок разработчика.

## 3. Ключевые технические решения

### 3.1 Целевое устройство
**Meta Quest 3 / 3S** (цветной passthrough, Scene/плоскости, доступ к камерам). Quest 2 / Pro — только без сканирования камерой (см. 3.3).
**[проверить]** Какая гарнитура есть у команды — от этого зависит выбор способа сканирования.

### 3.2 XR-стек
Остаёмся на **Unity OpenXR + XR Interaction Toolkit** (уже настроено и знакомо команде) и добавляем:

- `com.unity.xr.arfoundation` (6.x) — passthrough-камера, плоскости, якоря, raycast;
- `com.unity.xr.meta-openxr` (Unity OpenXR: Meta, 2.x) — провайдер этих функций для Quest.

Настройки: OpenXR → Android → включить **Meta Quest: Camera (Passthrough)**, **Planes**, **Bounding Boxes**, **Anchors**, **Session**; у камеры XR Origin — фон чёрный с alpha = 0, на камере `ARCameraManager` + `ARCameraBackground`; в URP отключить HDR/постобработку, мешающие прозрачности.

Альтернатива — Meta XR SDK (Core + MR Utility Kit). Даёт более богатую модель комнаты (MRUK) и потенциально готовое отслеживание QR, но это вторая система ввода/риг поверх XRI. Переходим на неё **только если** спайк по сканированию (3.3) покажет, что без MRUK QR не взлетает.

### 3.3 Сканирование QR — главный технический риск
Делаем через интерфейс `IBoxScanner`, чтобы игровая логика не зависела от способа:

| Реализация | Как работает | Когда используем |
|---|---|---|
| `DebugScanner` | Выбор коробки клавишами / лучом в редакторе (XR Device Simulator) | Разработка без шлема, автотесты |
| `CameraQrScanner` | Passthrough Camera API (Quest 3/3S, Horizon OS v74+, разрешение `horizonos.permission.HEADSET_CAMERA`) → кадр через `WebCamTexture` → декодирование **ZXing.Net** в фоне, только в момент «нажат курок сканера» | Основной вариант **[проверить]** |
| `MrukQrScanner` | QR-трекинг MR Utility Kit (экспериментальный, свежие версии MRUK) | Если доступен и стабилен **[проверить]** |
| `AnchorTagScanner` (фолбэк) | При калибровке игрок один раз сканирует/отмечает каждую коробку, на ней ставится виртуальная метка-якорь; дальше «скан» — луч сканера в метку | Если камера недоступна (Quest 2) или распознавание ненадёжно |

Геймплейная форма сканера: виртуальный ручной сканер в руке (XRI Grab). Нажатие курка → «луч» + звук → запрос кадра → результат на экранчике сканера (✔ / ✖ + номер коробки).

**Как понять, что коробку принесли к стойке:** у стойки есть зона выдачи (trigger volume). Выдача засчитывается, если правильная коробка отсканирована, когда сканер находится внутри зоны выдачи. Это не требует непрерывного трекинга физической коробки.

Печать этикеток: Editor-утилита генерирует PNG/PDF-лист с QR (`BOX-001…BOX-030`) + крупная подпись. Размер QR — не меньше 10×10 см **[проверить на дистанции 0,5–1,5 м]**.

### 3.4 Пространство комнаты
- Старт: экран калибровки — игрок указывает лучом место на полу (`ARRaycastManager` по плоскости пола) и поворот стойки. Позиция сохраняется через **ARAnchor** (позже — persistent anchor между сессиями).
- Плоскости пола/стола/потолка (`ARPlaneManager`) используются для: высоты потолка («Поставка»), коллайдеров, на которые кладутся виртуальные коробки, и проверки свободного пространства.
- Безопасность: клиенты и стойка не спавнятся вне Guardian/boundary; предупреждение «освободите проход» при поставке.

## 4. Репозиторий и командная работа

Сейчас доступа к GitHub из этой машины нет (не установлены git и GitHub CLI, нет сохранённых учётных данных). Что нужно:

1. Установить **Git for Windows** и **Git LFS**, при желании — **GitHub CLI** (`gh auth login`).
2. Создать репозиторий, добавить Unity `.gitignore` (`Library/`, `Temp/`, `Obj/`, `Logs/`, `UserSettings/`, `Build*/`, `apks/`, `*.csproj`, `*.sln`, `.idea/`, `.utmp/`).
3. `.gitattributes`: LFS для `*.fbx *.blend *.png *.psd *.tga *.wav *.mp3 *.ogg`, Unity YAML (`*.unity *.prefab *.asset`) — через UnityYAMLMerge.
4. Project Settings → Editor: Asset Serialization = Force Text, Version Control = Visible Meta Files (проверить).
5. Правила: ветка на задачу, PR с ревью; **одна сцена — один владелец**, остальные работают в префабах, чтобы не ловить конфликты в `.unity`.

## 5. Архитектура

### 5.1 Структура папок
```
Assets/_Project/
  Scenes/        Boot.unity, Game.unity
  Scripts/
    Core/        GameStateMachine, ShiftConfig (SO), ServiceLocator / bootstrap
    Room/        RoomSetup, CounterPlacement, AnchorStore
    Boxes/       BoxRegistry, BoxData (SO), VirtualBox
    Scanning/    IBoxScanner, ScannerTool, CameraQrScanner, DebugScanner, ...
    Orders/      Order, OrderGenerator, OrderService, ExtraRequest
    Customers/   Customer, CustomerQueue, CustomerSpawner
    Supply/      SupplyEvent, BoxDropper
    Scoring/     ScoreService, ShiftStats, Rating
    UI/          CounterBoard, ScannerScreen, ShiftSummary, Toasts
    Audio/       SfxPlayer
  Prefabs/  Art/  Audio/  Data/ (ScriptableObjects)  Tests/ (EditMode)
```

### 5.2 Основные модули и потоки
```
GameStateMachine: Boot → Calibration → ShiftRunning ⇄ SupplyEvent → ShiftSummary
                                   │
CustomerSpawner → CustomerQueue → Customer ──(просит)──► OrderService.CreateOrder()
                                                           │
ScannerTool ─► IBoxScanner ─► BoxRegistry.Resolve("BOX-002")
                                   │
                    OrderService.OnScan(box, isInHandoverZone)
                      ├─ неправильная коробка → штраф, фидбэк
                      ├─ правильная, вне зоны → «принесите к стойке»
                      └─ правильная, в зоне   → позиция выдана → ExtraRequest? → Complete
                                   │
                         ScoreService / ShiftStats ← события
```

- **Связь модулей через C#-события** (`OrderCompleted`, `BoxScanned`, `CustomerLeft`) — чтобы Scoring/UI/Audio подписывались, а не дергались напрямую.
- **Данные в ScriptableObject:** `BoxCatalog` (QR-строка → id, название, тип: реальная/виртуальная), `ShiftConfig` (кол-во клиентов, частота, терпение, вероятность доп. запросов, поставки).
- **Order:** `{ orderNumber, List<OrderLine{boxId, qty}>, List<ExtraRequest>, createdAt, deadline }`.
- **ExtraRequest:** `Bag`, `CountItems`, `Return`, `Rescan`, `ReplaceBox` — каждый как отдельная небольшая стратегия.
- **Реальные и виртуальные коробки — единый реестр.** Для виртуальной (из «Поставки») «скан» — это попадание луча сканера в её виртуальный QR.

## 6. План по этапам

Длительность спринтов — как в документе (по 2 недели). Роли: **Роман (Universal)** — код/интеграция, **Тимофей (Sedan)** — модели, анимации, UI/VFX/звук, **Григорий** — тесты.

- [ ] Пустые сцены `Boot`/`Game`, XR Origin (XRI Starter Assets) + XR Device Simulator.
- **DoD:** пустая сцена собирается в APK, на шлеме видна комната и висящий в воздухе куб.

### Спринт 1 — инфраструктура и спайки (недели 1–2)
- Роман: passthrough, плоскости, калибровка и установка стойки с якорем; **спайк сканирования** (`CameraQrScanner` vs `MrukQrScanner` vs фолбэк) → решение по 3.3 письменно в `docs/decisions/`; `DebugScanner` и интерфейс `IBoxScanner`.
- Тимофей: модели стойки ПВЗ, ручного сканера, первого клиента (low-poly, до ~10k треугольников на объект); простой экран на стойке.
- Григорий: тест-кейсы passthrough/трекинга при разном освещении; распечатать QR, замерить дистанцию и углы распознавания по итогам спайка; шаблон баг-репорта.
- **DoD:** стойка стоит на реальном полу и не «уплывает»; хотя бы один способ сканирования стабильно читает `BOX-001..003`.

### Спринт 2 — базовый игровой цикл = MVP (недели 3–4)
- Роман: `BoxRegistry`, `OrderGenerator`, `OrderService`, зона выдачи, `GameStateMachine`; EditMode-тесты на генерацию заказов и проверку скана.
- Тимофей: анимации клиента (подход, ожидание, получение, уход), табло над стойкой (номер заказа / «ТОВАРОВ В ЗАКАЗЕ: N»), экран сканера, звуки «верно/ошибка».
- Григорий: плейтесты распознавания с разных углов/дистанций, полный цикл MVP, баг-репорты.
- **DoD:** критерий MVP из раздела 2.

### Спринт 3 — «Поставка» и доп. услуги (недели 5–6)
- Роман: `SupplyEvent` — виртуальные коробки падают от высоты потолка (Rigidbody, коллайдеры плоскостей), их можно взять и поставить на пол/стол/кровать; очередь клиентов (2–3 слота); многопредметные заказы; возвраты; пакет.
- Тимофей: модели пакета и разных типов коробок, 2–3 варианта клиентов, VFX появления поставки.
- Григорий: физика падения (ничего не проваливается сквозь плоскости), выдача нескольких товаров, возвраты, безопасность перемещения.
- **DoD:** смена из 5 клиентов, включая одну поставку и один многопредметный заказ, проходится без ошибок логики.

### Спринт 4 — очки, смены, полировка (недели 7–8)
- Роман: `ScoreService` (бонусы/штрафы из документа), таймер смены, сложность через `ShiftConfig` (лёгкая/средняя/сложная), экран итоговой статистики, сохранение прогресса и расположения стойки (JSON + persistent anchors).
- Тимофей: звук, VFX успеха, оформление ПВЗ, голосовые/текстовые реплики клиентов.
- Григорий: сквозные сценарии, баланс сложности, проверка в комнатах разного размера, стабильность FPS (цель — 72 FPS на Quest 3).
- **DoD:** 3 уровня сложности, итоговая статистика, сборка релиз-кандидата.

### После MVP (этап 4 roadmap)
Случайные события (срочный заказ, забыл номер, похожие заказы), рейтинг и разблокировки, кастомизация ПВЗ, сохранение склада между сессиями.

## 7. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Камера шлема недоступна / QR плохо читается | Высокая | Спайк в спринте 1, интерфейс `IBoxScanner`, фолбэк на якоря-метки |
| Нет Quest 3/3S у команды | Средняя | Фолбэк-сканер; основная разработка в редакторе через Device Simulator |
| Конфликты в сценах при работе втроём | Средняя | Владелец сцены, работа в префабах, Force Text |
| Игрок спотыкается о коробки / мебель | Средняя | Boundary, предупреждения, ограничение зоны спавна, не спавнить коробки на пути |
| Производительность (passthrough + физика + декодирование QR) | Средняя | Декодировать только по нажатию, в фоне, уменьшенный кадр; профилирование на шлеме |
| Тяжёлый репозиторий | Низкая после очистки | Удалить старые модели и `apks/`, LFS |
