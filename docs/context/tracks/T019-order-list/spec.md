# T019 — Список заказов со статусами

## Зачем
Концепция: «интерфейс заказов». С очередью до трёх клиентов, возвратами, срочными и забывчивыми клиентами игроку
нужно видеть, кто чего ждёт. В `architecture.md` «явный список заказов со статусами» откладывался с T007.

## Что делаем
- Core: `OrderBook` в `Shift` — каждый визит смены и его состояние: `Waiting` (в очереди) → `AtCounter` (у стойки) →
  `Served` (выдан / возврат принят) или `Abandoned` (ушёл без заказа) или `Left` (ушёл из очереди: исчез по пути
  или вышло время смены). Завершённый визит своё состояние больше не меняет; событие `Changed` — после изменения.
- Табло: справа от основного табло панель «ЗАКАЗЫ» (до 7 строк): сначала клиент у стойки, затем очередь по порядку,
  затем завершённые (новые сверху). Срочные помечены «· срочно», номер забывчивого клиента — «№••81», полностью — только
  после выдачи. Цвета: у стойки — жёлтый, выдан — зелёный, ушёл — красный/серый. Панель скрыта, пока никто не пришёл;
  после конца смены остаётся рядом с итогами как журнал смены.

## Архитектура
- Состояния визитов — правило Core: `Shift` двигает записи там же, где меняет очередь (`Join`, `OpenNext`, выдача,
  уход, возврат, конец времени). Остальные только читают `Shift.Book`.
- Это не «единый `ActiveVisit` на стойке»: стойка по-прежнему знает заказ или возврат; книга — журнал смены поверх неё.
- Текст списка — `ShiftPresenter.OrderListText` (статический, тестируемый); панель — часть табло (`CounterBoard.ShowOrders`),
  поэтому презентеру не нужна новая зависимость.

## Критерии готовности
- EditMode: переходы состояний (выдача, уход без заказа, уход из очереди, конец времени, возврат), `Changed` после
  изменения; Editor: порядок и формат строк, скрытый номер забывчивого клиента, обрезка списка.
- PlayMode: после выдачи в настоящей сцене список показывает «№… — выдан».
