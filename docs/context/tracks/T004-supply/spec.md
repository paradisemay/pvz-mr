# T004 — Событие «Поставка»

## Зачем
Фирменная механика из концепции: склад формирует сам игрок. Посреди смены с потолка комнаты падают новые
коробки, их нужно принять на склад (отсканировать) и разложить по комнате; следующие клиенты приходят уже за ними.

## Правила
- Поставка наступает после того, как выдано `supplyAfterOrders` заказов (по умолчанию — после первого).
- Коробки поставки появляются на высоте потолка (плоскость потолка AR, иначе 2,4 м) в случайных свободных
  точках вокруг игрока (не над стойкой и не над игроком) и падают на пол/мебель.
- Пока коробка не отсканирована, её **нет на складе**: клиенты её не заказывают, выдать её нельзя.
- Сканирование коробки поставки = приёмка: `ScanStatus.Received`, коробка добавляется в каталог,
  +10 очков, на табло «Принято: X/N».
- Смена заканчивается, когда склад пуст **и** все коробки поставок приняты и выданы.
- Клиенты продолжают приходить во время поставки, если на складе есть что выдавать; если склад пуст —
  табло просит принять поставку.

## Модель
- Core `QrPattern` — генерация узора QR по id (единый для редактора и рантайма, без UnityEngine).
- Core `Shift.ExpectDelivery(records)` — коробки «в пути»; `Shift.Scan(id)` — приёмка или обычный скан;
  событие `BoxReceived`; `HasPendingIntake`; обновлённое `IsOver`.
- `ScoringRules.IntakeBox = 10`; `ShiftStats.BoxesReceived`.
- Runtime `SupplyDrop` — спавн коробок из общего префаба `Box_Supply` с QR-текстурой, созданной в рантайме.
- `ShiftSettings`: `supplyAfterOrders`, список коробок поставки (id + номер заказа), высота потолка по умолчанию.

## Критерии приёмки
- EditMode: приёмка, невозможность выдать непринятую коробку, конец смены с поставкой, очки за приёмку.
- PlayMode: полная смена с поставкой — 3 исходных + 3 коробки поставки, все 6 заказов выданы.
