# T005 — Многопредметные заказы и пакет

## Зачем
Из концепции: «ТОВАРОВ В ЗАКАЗЕ: N — найти и выдать все», «Мне ещё нужен пакет». Делает выдачу разнообразнее,
не меняя основного цикла.

## Правила
- **Многопредметный заказ:** несколько коробок с одним номером заказа. Клиент ждёт, пока выданы все;
  на табло «Коробок в заказе: осталось N»; каждую принятую коробку клиент держит в стопке.
- **Пакет:** с вероятностью `bagChance` (по умолчанию 0,5; в тестах управляется сидом) клиенту после выдачи всех
  коробок нужен пакет: реплика «Мне ещё нужен пакет!», табло «Клиенту нужен пакет». Пакеты лежат стопкой на стойке
  (раздатчик всегда держит один пакет). Пакет кладут в зону выдачи — заказ завершён, +20 очков.
- Пакет, положенный, когда он не нужен, — не ошибка: клиент говорит «Пакет не нужно», пакет остаётся.

## Модель
- Core: `Order.NeedsBag`; `OrderGenerator` решает `NeedsBag` через `IRandomSource` и `bagChancePercent`;
  `ServiceSession.BagDelivered`, `IsComplete = все коробки && (!NeedsBag || BagDelivered)`, `AwaitingBag`;
  `PickupDesk.HandOverBag(now)` → `BagOutcome` (`Accepted` / `NotNeeded` / `NoActiveOrder`), событие `BagHandedOver`;
  `ScoringRules.BagService = 20`; `ShiftStats.BagsGiven`.
- Runtime: `ParcelBag` (захватываемый), `BagDispenser` (держит один пакет на стойке), `HandoverZone.BagEntered`,
  стопка коробок у клиента, тексты в `ShiftPresenter`.
- Данные: в поставке BOX-101 и BOX-102 → один заказ 3307 (заказ из двух коробок).

## Критерии приёмки
- EditMode: многопредметный заказ, пакет нужен/не нужен, порядок «коробки → пакет», очки.
- PlayMode: полная смена с поставкой, заказом из 2 коробок и хотя бы одним пакетом.
