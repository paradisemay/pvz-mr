# T044 — Длинные смены и растущая очередь (#84)

Из #73: «сделать подлиннее смены — не 3 клиента, а штук 10, в зависимости от сложности; хотелось бы, чтобы
накапливалась очередь, если долго обслуживаем одного клиента».

## Было
3–5 заказов за смену (коробки пресета + поставка). Клиенты приходили, только когда в очереди освобождалось место.

## Решение
- **Заказов за смену** (пресет): Лёгкая 6, Обычная 10, Сложная 14. Склад дополняется сгенерированными заказами
  (`StockPlan.Extra`: 1–2 коробки, номера без случайных «похожих», `BOX-3xx`) — ручные коробки (похожая пара,
  большой заказ, поставка, запасные) остаются. Детерминировано для зерна.
- **Приход по часам** (`ArrivalClock`): первый клиент через `firstCustomerDelay`, дальше раз в `arrivalInterval`
  (Лёгкая 30 с, Обычная 22 с, Сложная 15 с, ±20 %), независимо от того, обслужен ли предыдущий. Если у стойки и в
  очереди пусто, следующий приходит через короткую паузу (быстрого игрока не держим).
- **Очередь до предела** (Лёгкая 3, Обычная 4, Сложная 4): пришедший к полной очереди не остаётся — его заказ
  остаётся на складе; в итогах «Не дождались очереди: N».
- Цикл смены разделён: `ArriveByTheClock` приводит клиентов, `RunShift` обслуживает голову очереди.
- Пресеты: число заказов, интервал и длина очереди задаются сборщиком и для существующих пресетов
  (`ConfigurePace`); таймер смены (Обычная 7 мин, Сложная 5 мин, Лёгкая без лимита) прежний.

## Проверка
- EditMode (`LongShiftTests`): часы прихода, пауза при пустой стойке, разброс; склад дополняется до 6/10/14,
  уникальные коробки, без похожих номеров, детерминирован; полная очередь отказывает и сохраняет заказ.
- PlayMode: очередь растёт до 4, пока игрок занят, затем новые не остаются; полная смена (10 заказов + поставка)
  проходится тестом; автопилот пульта проходит смену; куча из люка (до ~17 коробок) — в радиусе 2,2 м.
- Скриншоты: `09_queue` (очередь из четырёх), `06_shift_summary`.
