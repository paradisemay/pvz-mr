# T014 — Случайные события: срочный заказ и «забыл номер»

## Зачем
В концепции («Игровые ситуации», «Случайные события») прямо названы «срочный заказ» и «клиент забыл номер заказа».
Возвраты (T013) уже сделаны; эти два события дают разнообразие на Обычной и Сложной сложности.

## Что делаем
- **Срочный заказ.** Терпение клиента короче (`Shift.UrgentPatienceFactor`, 0.6 от обычного; торопит он, как и все,
  на 60 % своего терпения), за выдачу — бонус `ScoringRules.UrgentBonus` (+50). Табло: «СРОЧНО: заказ №N» красным,
  реплика «Срочно, опаздываю!».
- **Клиент забыл номер.** Клиент помнит только последние две цифры: «Забыл номер… кончается на 81», табло «Заказ №••81».
  Полный номер не показывают ни табло, ни реплики клиента (приветствие, «Это не мой заказ», «ушёл без заказа»),
  ни подсказка обучения. **Сканер намеренно показывает полный номер коробки** — это и есть способ найти заказ:
  игрок сканирует коробки и сверяет окончание.
  Событие выпадает, только если окончание однозначно среди всех заказов смены: на складе, в ожидающей приёмки
  поставке и в запланированной поставке.
- Шансы — в `ShiftSettings` (Лёгкая 0/0, Обычная 15/15, Сложная 25/20); бросок только при шансе > 0, чтобы смены без
  событий сохраняли прежнюю последовательность заказов (детерминизм тестов).
- Итоги смены: «Срочных заказов выдано: N».

## Архитектура
- Это **свойства заказа**, а не новый вид визита: `Order.IsUrgent`, `Order.ForgotNumber`, `Order.NumberHint`
  (неизменяемые, решаются в `OrderGenerator`). Клиент всё так же приходит за заказом, правила стойки не меняются.
  Поэтому единый `ActiveVisit` на стойке по-прежнему не нужен: видов визита остаётся два.
- Терпение для конкретного заказа считает `Shift` (`PatienceFor(order)`), бонус — `ShiftStats`.
- Формат «••81» и тексты — только в `ShiftPresenter` (`SpokenNumber`, `GreetingFor`); в Core только факт и подсказка.

## Ограничения
- Внеплановая поставка (`Shift.ExpectDelivery` извне, сейчас только в тестах), пришедшая уже после того, как
  забывчивый клиент встал в очередь, может сделать подсказку неоднозначной; плановая поставка учитывается.

## Критерии готовности
- EditMode: генератор (шансы, однозначность подсказки с учётом поставки, детерминизм при нулевых шансах), терпение
  срочного заказа и проверка коэффициента, бонус и счётчик.
- PlayMode: забывчивый клиент в настоящей сцене — табло и реплики (включая «не мой заказ») без полного номера,
  сканер показывает полный номер, выдача.
