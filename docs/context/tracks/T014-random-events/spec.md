# T014 — Случайные события: срочный заказ и «забыл номер»

## Зачем
В концепции («Игровые ситуации», «Случайные события») прямо названы «срочный заказ» и «клиент забыл номер заказа».
Возвраты (T013) уже сделаны; эти два события дают разнообразие на Обычной и Сложной сложности.

## Что делаем
- **Срочный заказ.** Клиент торопится с самого начала: терпение короче (`Shift.UrgentPatienceFactor`, 0.6 от обычного),
  за выдачу — бонус `ScoringRules.UrgentBonus` (+50). Табло: «СРОЧНО: заказ №N», реплика «Срочно! Опаздываю!».
- **Клиент забыл номер.** Клиент помнит только последние две цифры: «Заказ №••81». Номер полностью не показывается
  нигде, пока заказ не выдан (в том числе в реплике «Это не мой заказ»). Найти коробку помогает сканер.
  Событие выпадает, только если окончание однозначно: ни у одного другого заказа на складе нет тех же двух последних цифр.
- Шансы — в `ShiftSettings` (Лёгкая 0/0, Обычная 15/15, Сложная 25/20); бросок только при шансе > 0, чтобы смены без
  событий сохраняли прежнюю последовательность заказов (детерминизм тестов).
- Итоги смены: «Срочных заказов выдано: N».

## Архитектура
- Это **свойства заказа**, а не новый вид визита: `Order.IsUrgent`, `Order.ForgotNumber`, `Order.NumberHint`
  (неизменяемые, решаются в `OrderGenerator`). Клиент всё так же приходит за заказом, правила стойки не меняются.
  Поэтому единый `ActiveVisit` на стойке (см. «Решения T013») по-прежнему не нужен: видов визита остаётся два.
- Терпение для конкретного заказа считает `Shift` (`PatienceFor(order)`), бонус — `ShiftStats`.
- Тексты — только в `ShiftPresenter`; отображаемый номер — `Order.DisplayNumber` не делаем: формат «••81» —
  решение представления, в Core только факт и подсказка.

## Критерии готовности
- EditMode: генератор (шансы, однозначность подсказки, детерминизм при нулевых шансах), терпение срочного заказа,
  бонус и счётчик, подсказка не раскрывает номер.
- PlayMode: забывчивый клиент в настоящей сцене — табло без полного номера, выдача по скану.
