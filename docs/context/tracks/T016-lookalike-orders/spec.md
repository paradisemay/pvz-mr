# T016 — Похожие заказы

## Зачем
В концепции среди игровых ситуаций и случайных событий — «похожие заказы»: номера, которые легко перепутать.
Это ловушка для невнимательного игрока и повод внимательно читать экран сканера.

## Что делаем
- Правило Core `OrderNumbers.LookAlike(a, b)`: разные номера одной длины (не короче 3), у которых отличается ровно
  один символ (5812 / 5912) или переставлены два соседних (2781 / 2718).
- `PickupDesk`: чужая коробка с похожим номером помечается флагом `LooksLikeTheWantedOrder` — и при скане
  (`ScanOutcome`), и при выдаче (`HandoverOutcome`).
- Сканер: «Заказ №2718 / ПОХОЖ — / НЕ ТОТ!» вместо «НЕ ТОТ ЗАКАЗ». Клиент при выдаче такой коробки:
  «Похож, но не мой! Мне нужен №…».
- Клиенту, забывшему номер (T014), флаг не ставится: сканер не должен подсказывать больше, чем сказал клиент.
- Данные: в поставке заказ 3307 (2 коробки) и **2718** — похожий на 2781 со склада (было 6021).
  Окончания номеров по-прежнему различны, поэтому «забыл номер» однозначен (охраняется тестом).
- Очки не меняются: ошибка наказывается, как и раньше, только при выдаче неверной коробки.

## Архитектура
- Сходство номеров и подсказка забывчивого клиента — `OrderNumbers` (Core, без `UnityEngine`); тексты — `ShiftPresenter`.
- Флаг — часть исхода (как `BoxOrderNumber`), а не новый статус: счётчики и подсказки обучения не меняются.
- Похожая пара — данные пресетов, а не генерация (коробки — объекты сцены); если «похожие заказы» станут событием с
  шансом, генерацию можно перенести в Core.

## Критерии готовности
- EditMode: таблица случаев `LookAlike`, связь с подсказкой (`SameHint`), флаг в скане и выдаче, без флага для
  забывчивого клиента, флаг только для чужих коробок; Editor: одинаковая поставка во всех пресетах, похожая пара
  в Обычной и Сложной, различные окончания номеров во всех пресетах.
- PlayMode-набор проходит без изменений.
