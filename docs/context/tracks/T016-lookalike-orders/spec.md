# T016 — Похожие заказы

## Зачем
В концепции среди игровых ситуаций и случайных событий — «похожие заказы»: номера, которые легко перепутать.
Это ловушка для невнимательного игрока и повод внимательно читать экран сканера.

## Что делаем
- Правило Core `OrderNumbers.LookAlike(a, b)`: разные номера одной длины, у которых те же цифры в другом порядке
  (2781 / 2718) или отличается ровно одна цифра (5812 / 5912).
- `PickupDesk.Scan`: для чужой коробки (`OtherOrder`) поднимается флаг `ScanOutcome.LooksLikeTheWantedOrder`,
  если её номер похож на номер заказа клиента у стойки.
- Сканер: «Заказ №2718 / ПОХОЖ, НО НЕ ТОТ!» вместо обычного «НЕ ТОТ ЗАКАЗ».
- Данные: в поставке заказ 3307 (2 коробки) и **2718** — похожий на 2781 со склада (было 6021).
  Окончания номеров остаются различными, поэтому «забыл номер» (T014) по-прежнему однозначен.

## Архитектура
- Сходство номеров — правило (Core, без `UnityEngine`), формулировка — `ShiftPresenter`.
- Флаг — часть исхода скана (как `BoxOrderNumber`), а не отдельное событие: стойка уже поднимает `BoxScanned`.
- Очки не меняются: ошибка наказывается, как и раньше, только при выдаче неверной коробки.

## Критерии готовности
- EditMode: таблица случаев `LookAlike` (симметрия, длина, равные номера, повторяющиеся цифры), флаг в скане стойки.
- Пресеты пересозданы с новым номером поставки; PlayMode-набор проходит без изменений.
