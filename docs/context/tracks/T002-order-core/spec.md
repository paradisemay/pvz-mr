# T002 — Core: коробки, заказы, стойка

## Зачем
Правила игры должны проверяться без шлема и без сцены — юнит-тестами.

## Модель
- `BoxId` — строковый идентификатор QR (`BOX-001`), сравнение без учёта регистра и пробелов по краям.
- `BoxRecord` — коробка на складе: `BoxId` + номер заказа (`1435`).
- `BoxCatalog` — склад: добавить, найти по id, убрать выданную, список оставшихся.
- `Order` — неизменяемое описание заказа: номер + список коробок (в MVP — одна).
- `ServiceSession` — обслуживание одного клиента: заказ, время начала, выданные коробки, ошибки.
  Хранит изменяемый прогресс, чтобы `Order` оставался неизменяемым (подготовка к очереди клиентов).
- `OrderGenerator` — случайный заказ из оставшихся коробок (`IRandomSource`).
- `PickupDesk` — стойка:
  - `OpenOrder(order, now)` — клиент подошёл; нельзя открыть второй, пока первый не закрыт;
  - `Scan(boxId)` → `ScanOutcome`: `Matches` / `OtherOrder` / `UnknownBox` / `NoActiveOrder` (+ номер заказа коробки);
  - `Handover(boxId, now)` → `HandoverOutcome`: `Accepted` / `WrongBox` / `UnknownBox` / `NoActiveOrder`;
    при `Accepted` коробка уходит со склада, заказ закрывается;
  - события `OrderOpened`, `BoxScanned`, `OrderCompleted`, `WrongHandover`.
- `ShiftStats` — счёт: +100 за заказ, +50 если без ошибочных выдач, бонус за скорость (≤30 с: +50, ≤60 с: +25),
  −25 за неправильную выдачу (счёт не опускается ниже 0); считает выданные заказы, ошибки сканирования/выдачи, среднее время.
- `PickupDesk` сначала полностью обновляет состояние, потом поднимает события — обработчики могут
  безопасно вызывать стойку (например, открыть следующий заказ из `OrderCompleted`).
- `OpenOrder` проверяет, что все коробки заказа на складе и действительно относятся к этому номеру.

## Критерии приёмки
- Все сценарии выше покрыты EditMode-тестами, тесты зелёные в batchmode.
- `Pvz.Core` не ссылается на `UnityEngine`.
