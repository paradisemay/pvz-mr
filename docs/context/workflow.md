# Workflow

## Context-Driven Development
Перед кодом — контекст. Каждая единица работы — **трек** в `docs/context/tracks/<id>/`:
- `spec.md` — что и зачем, критерии приёмки;
- `plan.md` — задачи с чекбоксами, обновляются по ходу работы.

Реестр треков и их статусы — [tracks.md](tracks.md). Документы `product.md`, `tech-stack.md`, `architecture.md`
обновляются, когда меняется решение, а не задним числом.

## Ветки и PR
```
feature/<track-id>-<slug>  ──PR──►  dev  ──PR──►  main
```
- Одна feature-ветка = один трек (или его законченная часть).
- PR в `dev`: описание, что сделано, как проверено, скриншоты из Unity при изменениях сцены.
- PR `dev → main` — когда в `dev` стабильный инкремент (тесты зелёные, сцена собирается).
- Слияние — merge commit (история треков видна).

## Ревью
Каждый PR перед слиянием проходит два независимых ревью «чистыми» агентами (без контекста автора):
1. **Code review** — корректность, баги, тестируемость.
2. **Architecture review** — соответствие `architecture.md`: направление зависимостей, связность, расширяемость.
Найденное исправляется в той же ветке; итог ревью кратко фиксируется в описании PR.
PR только с документацией ревьюится автором (агентное ревью не обязательно).

## Definition of Done
- Компилируется в batchmode без ошибок (`error CS` в логе отсутствует).
- EditMode-тесты зелёные; для изменений игрового цикла — PlayMode-тест зелёный.
- Сцена пересобирается `PvzSceneBuilder.BuildAll`.
- Трек и `tracks.md` обновлены.
